# Mashtots — классификация армянских рукописных букв

Решение для соревнований [Mashtots Dataset](https://www.kaggle.com/competitions/mashtots-dataset)
и [Mashtots Dataset v2](https://www.kaggle.com/competitions/mashtots-dataset-v2):
78 классов (39 букв × заглавная и строчная), изображения 64×64 в градациях
серого, 70 060 штук в обучающей части.

## Файлы

| Файл | Для чего |
|---|---|
| `mashtots_kaggle.ipynb` | рабочий вариант для запуска в Kaggle: пути `/kaggle/input`, GPU, TTA, `submission.csv` |
| `mashtots_tutorial.ipynb` | учебный вариант: каждая строка с комментарием, разбор альтернатив и запускаемые демонстрации трёх типичных ловушек |
| `mashtoc_letters.ipynb` | локальный прогон с разбором ошибок предыдущей версии модели |
| `kernel-metadata.json` | конфигурация для отправки ноутбука через `kaggle kernels push` |
| `requirements.txt` | зависимости для локального запуска (в Kaggle не нужны) |

## Запуск в Kaggle

1. [Create → Notebook](https://www.kaggle.com/code), затем `File → Import Notebook` и загрузить `mashtots_kaggle.ipynb`.
2. `Add Input` → нужное соревнование.
3. `Settings → Accelerator: GPU T4 x2`. На CPU прогон будет очень долгим.
4. `Save & Run All (Commit)`. После завершения `submission.csv` появится в Output, оттуда — `Submit`.

Каталог с классами и тестовая часть ищутся автоматически, поэтому подходят оба
соревнования и любая вложенность (`Train/` или `Train/Train/`). Первая ячейка
печатает содержимое `/kaggle/input` и колонки всех CSV — если автопоиск не
сработал, из её вывода видно, какой путь подставить.

Через CLI (нужны `pip install kaggle` и `~/.kaggle/kaggle.json`):

```bash
# в kernel-metadata.json подставить свой ник Kaggle в поле "id";
# для второго соревнования заменить competition_sources на mashtots-dataset-v2
kaggle kernels push -p .
```

## Локальный запуск

```bash
pip install -r requirements.txt
kaggle competitions download -c mashtots-dataset -p data/mashtots
unzip data/mashtots/mashtots-dataset.zip -d data/mashtots
jupyter notebook mashtoc_letters.ipynb
```

Ожидаемая раскладка данных:

```
data/mashtots/
  Train/0/1.png ... Train/77/*.png    # 78 папок-классов
  new_test/ либо new_test.csv          # тест соревнования, опционально
  sample_submission.csv                # опционально
```

Параметры `mashtoc_letters.ipynb` переопределяются переменными окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MASHTOTS_DATA` | `data/mashtots` | корень датасета |
| `MASHTOTS_EPOCHS` | `30` | максимум эпох, есть early stopping |
| `MASHTOTS_MAX_PER_CLASS` | все | ограничить число изображений на класс |
| `MASHTOTS_DIAGNOSTIC` | `1` | `0` — пропустить раздел «Диагностика» |

## Ключевые решения

| Решение | Причина |
|---|---|
| разрешение 64×64, родное | ресайз вверх не добавляет информации, но умножает время и память: 200×200 — это 2.6 ГиБ вместо 274 МиБ на датасет |
| хранение в `uint8` | 274 МиБ против 1.07 ГиБ во `float32`; Keras всё равно приводит батч к float сам |
| метка класса = `int(имя папки)` | `image_dataset_from_directory` назначает метки по строковой сортировке, из-за чего папка `10` получила бы метку 2 |
| нормализация слоем `Rescaling` внутри модели | применяется и при обучении, и при `predict`, поэтому препроцессинг нельзя рассинхронизировать |
| аугментация слоями `Random*`, без отражений | считается на GPU и сама отключается на инференсе; отражённая буква — это неверная метка, буквы зеркально несимметричны |
| заливка после сдвига нулями | фон датасета чёрный, дефолтный `fill_mode="reflect"` затащил бы в кадр обрывки штриха |
| две свёртки 3×3 вместо одной 5×5 | то же поле обзора, 18 496 параметров против 25 632, плюс нелинейность между ними |
| голова без узких слоёв | `Dense(2)` перед выходом на 78 классов полностью убивает обучение |
| `BatchNormalization(momentum=0.9)` | с дефолтным `0.99` скользящие статистики сходятся только к ~2000 шагам, и всё это время валидация показывает `1/78` |
| `sparse_categorical_crossentropy` | не нужна матрица `N×78` и не нужно хардкодить число классов |
| разбиение 80/10/10 со `stratify` | честная оценка на нетронутом тесте, все классы во всех частях |
| сопоставление submission по идентификатору | файлы читаются лексикографически (`1, 10, 100, 11, 2`), а `sample_submission` обычно отсортирован численно |

Подробный разбор каждого пункта с альтернативами — в `mashtots_tutorial.ipynb`.

## Ориентиры при отладке

Если модель не учится, сравните метрики с двумя числами:

* `ln(78) = 4.3567` — кросс-энтропия равномерного распределения по 78 классам;
* `1/78 = 0.0128` — accuracy случайного угадывания.

Если обе метрики стоят на этих значениях, сеть выдаёт константу независимо от
входа. Если же train растёт, а val стоит на `1/78` при **растущем** val-loss —
причина в слоях, по-разному работающих в обучении и инференсе, то есть почти
всегда в BatchNorm с несошедшимися статистиками.
